# 🍋 Сайт Lemon Score

Статический сайт для GitHub Pages: каталог раскрасок, которые оценили пользователи расширения.
Сборки нет — обычные HTML, CSS и JS. Данные берутся из Supabase, обложки — с серверов картинок Amazon.

```
lemon-score-site/
├── index.html   ← разметка
├── styles.css   ← оформление (светлая и тёмная тема)
├── app.js       ← логика: каталог, фильтры, страницы авторов, связь с расширением
├── config.js    ← адрес и публичный ключ Supabase, ссылка на расширение
├── icon.svg     ← значок вкладки
└── .nojekyll    ← чтобы GitHub Pages отдавал файлы как есть
```

## Что умеет

- **Только оценённые книги.** Книга попадает на сайт, когда у неё появляется хотя бы одна оценка.
- **Фильтр по вердикту:** «Скорее не ИИ», «Спорно», «Подозрение на ИИ», со счётчиками. Вердикт считается так же, как в расширении: до 3 оценок по обычному среднему (с пометкой «мало оценок»), дальше по сглаженному.
- **Поиск** по названию, автору или ASIN, **порядок** (недавно оценённые, больше всего оценок, сначала похожие или непохожие на ИИ) и **магазин** (amazon.com, .de, ...).
- **Авторы:** список всех авторов с распределением их книг по вердиктам. На странице автора есть те же фильтры, но только по его книгам.
- **«Вы оценили».** Если у посетителя стоит расширение, на обложках его книг видна его оценка, а вкладка «Мои оценки» показывает только их.
- Русский и английский: язык выбирается по браузеру, переключатель стоит в шапке.
- Все фильтры хранятся в адресе (`#/?v=suspicious&sort=most_rated`), так что ссылкой можно поделиться.

## Как сайт узнаёт, что вы оценили книгу

Сайт не может сам заглянуть в данные расширения, поэтому расширение подключает к страницам сайта маленький скрипт `site-bridge.js` (раздел `content_scripts` в `manifest.json`):

1. Сайт отправляет `window.postMessage({source: 'lemon-score-site', type: 'getMyRatings'})`.
2. `site-bridge.js` передаёт запрос в `background.js`, тот вызывает `get_my_ratings(device_id)` в Supabase.
3. Сайт получает только список «магазин + ASIN + оценка». Сам ID устройства странице не передаётся.

Если расширения нет, сайт через ~1 секунду перестаёт ждать ответа и показывает кнопку «Установить расширение».

## Запуск

### 1. Обновить базу
Supabase → **SQL Editor** → вставить весь обновлённый `supabase/schema.sql` → **Run**. Скрипт можно запускать повторно, старые оценки сохранятся. Он добавляет таблицу `books` (название, автор, обложка) и функции для сайта: `list_books`, `count_books`, `list_authors`, `get_my_ratings`, `upsert_book_meta`.

### 2. Опубликовать сайт на GitHub Pages
1. Создайте на GitHub публичный репозиторий, например `lemon-score-site`.
2. Загрузите в него **содержимое** папки `lemon-score-site` (файлы должны лежать в корне репозитория). Через сайт GitHub: **Add file → Upload files**.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
4. Через минуту сайт откроется по адресу `https://ВАШ-ЛОГИН.github.io/lemon-score-site/`.

### 3. Подключить расширение к сайту
1. В `lemon-score/manifest.json` замените `YOUR-GITHUB-USERNAME` на свой логин GitHub (второй блок `content_scripts`).
2. На `chrome://extensions` нажмите кнопку обновления у Lemon Score и перезагрузите сайт. В шапке появится «Вы оценили N книг».

`http://localhost` и `http://127.0.0.1` уже разрешены, поэтому сайт с расширением можно проверить локально:
`python -m http.server 8000` в папке сайта, затем открыть `http://localhost:8000`.

### 4. Ссылка на расширение
В `config.js` поменяйте `INSTALL_URL` на страницу расширения в Chrome Web Store, когда оно там появится.

## Откуда данные о книгах

Сайт на GitHub Pages не может сам читать Amazon: браузер блокирует такие запросы (CORS), а Amazon защищается от парсинга. Поэтому:

- **Название, автора и ссылку на обложку присылает расширение** вместе с оценкой: в этот момент оно уже открыто на странице книги.
- Для книг, оценённых старой версией расширения, данные дошлются автоматически, когда кто-нибудь с новой версией откроет страницу книги.
- Если обложки нет, сайт пробует старый адрес картинки Amazon по ASIN, а если не выходит, рисует заглушку с лимоном.
- Сервер принимает обложки только с доменов картинок Amazon и не даёт перезаписать уже заполненные название и автора (пока записи нет 30 дней). Так одна поддельная отправка не может переименовать чужую книгу. Исправить данные вручную можно в Supabase: **Table Editor → books**.

Официальный путь получить данные Amazon — Product Advertising API. Для него нужен аккаунт Amazon Associates с продажами по партнёрским ссылкам. Если он появится, можно добавить GitHub Action, который по расписанию обновляет таблицу `books` через API.

## Ограничения

- Каталог считается на лету по всей таблице оценок. До десятков тысяч оценок это быстро. Дальше стоит перенести сводку в материализованное представление.
- Авторы склеиваются по имени без учёта регистра и лишних пробелов. Разные написания одного автора («J. Basford» и «Johanna Basford») будут разными авторами.
